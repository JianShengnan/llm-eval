# Qwen3-8B 语音导航意图识别 · 专用微调（SFT）数据集说明

> 生成脚本：`build_sft_dataset.py`；统计与校验见 `sft_dataset_info.json`。本 md 由脚本自动生成，重跑即刷新数字。

## 一、结论：原来的评测集 jsonl **不能直接用于微调**

| # | 问题 | 具体证据 |
| :-- | :--- | :--- |
| 1 | **测试集泄漏** | 这 432 条是冻结的专业能力测试集，`datasets/intent_routing/dataset_info.json` 已记录源 sha256。拿它训练，之后用同一套评测代码测出的准确率完全失效。 |
| 2 | **标签覆盖极低** | 只命中 53/495 个末级标签（10.71%）、53/498 个节点（10.64%），445 个节点零命中；`人工服务` 独占 164 条（37.96%）。8B 模型微调后会强烈偏向高频通用意图。 |
| 3 | **prompt 形态是评测专用** | 每条把 498 条候选树整段内联，平均 6369 字符（约 3.2k tokens）。直接当训练语料，单次训练成本极高，且模型会学成「依赖超长候选列表做检索」。 |
| 4 | **不是 SFT 格式** | 每条是 `{sample_id, prompt, ground_truth, ...}` 的评测记录，没有 `messages` / `instruction-output` 结构，LLaMA-Factory、ms-swift 无法直接读取。 |
| 5 | **只有单一正样本、单一模板** | 432 条共用同一段指令、同一份候选树；没有指令多样性、没有「小模型给错要纠正」的样本、没有域外拒识与 ASR 噪声样本。 |
| 6 | **真实语料几乎被抽空** | `export_11.xlsx` 共 1041 条 user 行，其中 602 条标注为空或 NULL、432 条已进评测集；仅按源行排除后只剩 7 条有效标注，且这些行全部属于评测集出现过的会话，按会话级隔离后**训练集中真实标注正样本为 0 条**（0 个标签）。 |

> ⚠️ **重要前提**：严格隔离版（`sft_train.jsonl`）里**没有任何一条带真实人工意图标注的正样本**，正样本全部由意图树合成。它的定位是「格式对齐 + 495 个标签的冷启动」，**不能单独支撑上线**。真实标注只有两条获取途径：`--include-eval`（会污染测试集，见第四节）或补标（见第六节）。

因此：另建一份**格式对齐、标签全覆盖、与评测集零重叠**的 SFT 数据集；同时必须说明其中合成样本的定位（见第六节）。

## 二、数据集构成

| 来源类型 | 条数 | 说明 |
| :--- | ---: | :--- |
| `real_labeled` | 0 | export 中未被评测集使用、且**整段会话不在评测集**的真实标注语句，带真实历史对话与机器识别意图 |
| `real_noise` | 60 | export 中真实的纯英文系统词 / 单数字 / 单符号噪声行，标为 `集外` 或 `简短词`，是最有价值的真实负样本 |
| `synthetic_template` | 962 | 按意图树节点名称用 8 种口语句式生成，二三级节点额外带父级上下文；用于让模型**认识全部标签空间** |
| `synthetic_oral` | 30 | 「人工服务 / 问候 / 肯定 / 否定 / 结束语」等通用交互意图，用真实口语短句生成（业务模板造句不合理） |
| `synthetic_ood` | 20 | 明确的域外问法（天气、外卖、写诗等），标签 `集外`，训练拒识 |

**总计 1072 条**；候选树模式 `full`（`full` = 与评测一致的 498 条层级路径）。平均 prompt 6123 字符；覆盖 497/498 个意图节点（99.80%）。

未覆盖节点：`NULL`。这些是评测阶段已剔除的字面占位标签，不应作为有效意图输出，因此刻意不生成训练样本。
## 三、格式与对齐口径（关键）

每行一条 JSON，采用 LLaMA-Factory / ms-swift 通用的 `messages` 格式：

```json
{"messages": [
  {"role": "user", "content": "你是银行语音导航系统的意图识别专家。…【候选意图树】…【历史对话】…【客户当前对话】…【小模型识别意图】…【输出】"},
  {"role": "assistant", "content": "个人账户交易明细查询"}
], "metadata": {"sample_id": "T00001", "source_type": "synthetic_template", "group_key": "synth:…",
                 "label": "个人账户交易明细查询", "node_path": "…", "split": "train", …}}
```

**只有一条 `user` + 一条 `assistant`，刻意不加 `system` 角色。** 原因：`geval/professional.py::IntentRoutingTask.build_messages()` 明确返回 `[{"role":"user","content": question}]`，评测时框架只发单条 user message。若 SFT 训练成 system+user，微调后的模型在评测 prompt 上会分布不匹配。

- `instruction_variant`：`v0` 直接复用 `build_dataset.build_prompt()` 原文（与评测 100% 同构），`v1/v2` 为等价措辞改写，防止过拟合单一指令。
- `assistant` 只输出**末级意图名称**，与 `IntentRoutingTask.extract_intent()` 的判分对象一致；不输出路径、不加解释、不换行。
- `small_model_intent` 刻意混入正确标签 / `未识别` / 随机错标签，对应 prompt 第 3 条「小模型意图仅供参考」，训练模型纠正小模型而非盲从。
- 节点描述 `description_clean` **没有进训练输入**：那是客服的应答话术，把答案当用户输入会制造错误的监督信号；只保留在 metadata 的 `node_path` 供追溯。

| :--- | :--- |
| `all_labels_in_tree` | PASS |
| `messages_shape_ok` | PASS |
| `no_eval_source_row` | PASS |
| `no_eval_utterance` | PASS |
| `no_group_cross_split` | PASS |
| `no_empty_utterance` | PASS |

- 默认文件**不含**冻结评测集任何 `source_row`、任何 `current_utterance` 原文；评测集出现过的 140 个会话，整段会话都不进训练集。

### 4.1 可选变体 `--include-eval`：唯一能立刻拿到真实标注的方式

`python build_sft_dataset.py --include-eval` 会额外产出单一的 `sft_train_with_eval.jsonl`（= 默认 train 841 条 + 432 条真实人工标注样本），dev / test 沿用默认文件、不重复落盘。新增样本指令用与评测完全一致的 `v0`，避免格式漂移。这是当前唯一能立刻拿到真实标注正样本的产物。

**代价（必须接受）**：原 `语音导航意图识别评测数据集.jsonl` 从此成为训练集的一部分，继续用它做专业能力评测 = 训练集自测，准确率虚高、结论无效。选用这版必须：

1. 另建一套**独立、不与任何训练样本同会话**的测试集（优先按 445 个零命中节点补标）；
2. 用 `scripts/prepare_professional_dataset.py --input <新测试集> --out datasets/intent_routing_v2` 转换成框架格式，评测配置指向新数据目录；
3. 所有对外结论只基于新测试集，旧 432 条只作为训练拟合情况参考。

默认三个文件不含这 432 条；`sft_dataset_info.json` 的 `eval_included_in_default_files=false` 即为凭据。上面 `checks` 也只针对默认严格隔离版，不代表 with_eval 版未污染。

## 五、Qwen3-8B 微调建议

**框架**：LLaMA-Factory 或 ms-swift，LoRA / QLoRA。建议配置：

```yaml
# LLaMA-Factory 训练参数（示例，按显存调整）
model_name_or_path: Qwen/Qwen3-8B
stage: sft
finetuning_type: lora
lora_rank: 32            # 标签空间 495 类，r=16 偏小
lora_alpha: 64
lora_target: q_proj,k_proj,v_proj,o_proj,gate_proj,up_proj,down_proj
learning_rate: 1.0e-4
num_train_epochs: 2      # 合成样本多，>3 轮极易过拟合模板
per_device_train_batch_size: 1
gradient_accumulation_steps: 8
cutoff_len: 4096         # full 模式 prompt 约 3.2k tokens，必须 >=4096
template: qwen3
flash_attn: fa2
```

**Qwen3 特有的两个坑**：

1. **关闭 thinking**：Qwen3 默认开启推理模式，会把 64 token 的输出预算吃光并输出一大段分析。训练数据里 assistant 只有标签，需在推理侧传 `extra_body.chat_template_kwargs.enable_thinking=false`（评测配置已带）。
2. **不要混用 system 角色**：见第三节；`template: qwen3` 会把 messages 渲染成 `<|im_start|>user … <|im_start|>assistant …`，与评测端一致。

`dataset_info.json` 片段（LLaMA-Factory）：

```json
{"voice_nav_sft": {"file_name": "sft_train.jsonl",
  "formatting": "sharegpt",
  "columns": {"messages": "messages"},
  "tags": {"role_tag": "role", "content_tag": "content", "user_tag": "user", "assistant_tag": "assistant"}}}
```

训练完成后用 `../03_Qwen3-8B评测/Qwen3-8B专业能力评测说明.md` 里的命令，把端点指到微调后的模型，与微调前用不同 `--run-name` 做 A/B。

## 六、局限（务必读完）

- **这是「格式对齐 + 标签空间冷启动」数据集，不是生产级微调语料。** 合成样本占 94.4%，真实标注仅 0 条；问法由节点名称套句式生成，与真实 ASR 口语（含语气词、断句、识别错误）差距明显。
- **覆盖率 ≠ 质量**：497/498 个节点都出现过，但每个节点只有 2 条左右，且是同义改写，不足以学会细粒度区分（例如「借记卡换卡」vs「借记卡挂失换卡」）。
- **内部 dev/test 只验证格式与标签记忆**，不能用来宣称模型线上效果；真正的效果指标只能用冻结的 432 条专业评测集。
- **上线前必须补真实语料**：按 `../01_分布分析/意图节点命中明细.csv` 中「是否命中=否」的 445 个节点补标真实用户语句（每节点 ≥5 条、含多轮上下文），或用教师模型生成后人工校验，再与本数据集合并训练。
- export 中另外 549 条 `是否无效意图=是` 且标注为空的 user 行是真实客户语句但无标签，可用于**继续预训练 / 领域适配**，不要当 SFT 监督信号。

**三条可执行的路径（按推荐度）**：

| 路径 | 做法 | 代价 |
| :--- | :--- | :--- |
| A · 补标后训练（推荐） | 按 `../01_分布分析/意图节点命中明细.csv` 中零命中的 445 个节点补标真实用户语句（每节点 ≥5 条，含多轮上下文），与本数据集合并训练 | 需要标注人力，但结果可信 |
| B · 冷启动先行 | 先用本数据集微调，让 Qwen3-8B 学会输出格式与 495 个标签，上线前再用真实日志做一轮增量微调 | 快，但中间态不可上线 |
| C · 用 `--include-eval` | 用 432 条真实标注训练，同时另建独立测试集 | **原评测集作废**，需重建评测链路 |

无论选哪条，最终效果都必须用一套**训练期间完全未见过的会话**来评，命令见 `../03_Qwen3-8B评测/Qwen3-8B专业能力评测说明.md`。
