## 1. 项目目标

把银行标注平台导出的语音导航对话数据，整理成可复用的两套资产，并完成评测/微调闭环：

1. **专业能力评测集**：评测任意大模型在「语音导航意图识别」上的能力 —— 输入 = 客户当前对话 + 历史对话 + 小模型识别意图 + 意图树，输出 = 从意图树中选出的唯一意图名称，人工标注为真实答案。
2. **微调数据集**：为 Qwen3-8B 构建专用 SFT 数据，目标是得到一个专门用于语音导航意图识别的 8B 模型。
3. **评测执行**：用自建评测框架 `llm-general-eval`（geval）对模型（原始 / 微调后）做专业能力评测，并记录 token 与耗时。

## 4. 业务口径（已与需求方确认，**不可擅自更改**）

1. **客户当前对话** = export 中 `说话人 == user` 的 `语句文本`；跳过空文本、纯英文（含 playover/timeout/sys_err 等系统信号）、单个数字、单个符号。
2. **历史对话** = 同一会话ID下、`轮次序号` 小于当前行的**最近 5 行**（不足按实际），含客户与客服，带「客户：/客服：」角色标签，清洗 `[p1]` `[=hai2]` `[n2]` 等韵律/ASR 标记及孤立方括号。
3. **小模型识别意图** = `机器识别意图` 原值（含「未识别」）。
4. **意图树** = FAQ + 菜单两个模板合并去重后的层级路径（不含节点描述），每条样本内联。
5. **真实答案** = `人工标注意图名称`；剔除名称为空与字面 `NULL` 的样本；保留集外、人工服务、问候等通用交互意图。
6. 交付格式：Excel + JSONL 双份；评测集是**冻结测试集**，绝不能进训练 / few-shot。

## 8. 关键技术决策与坑（接手者必读）

1. **`dedupe` 必须为 false**：432 条 prompt 前 200 字相同（共享候选树），通用去重会压成 1 条。任务类与配置双保险，别删。
2. **SFT 与评测同构**：评测只发 `[{"role":"user","content": prompt}]`（无 system）。SFT 若加 system，微调后模型在评测 prompt 上分布不匹配。`v0` 指令直接复用 `build_dataset.build_prompt()`。
3. **Qwen3 必须关 thinking**：`extra_body.chat_template_kwargs.enable_thinking=false`，且 `max_tokens=64`、`temperature=0`（缓存只对确定性请求生效）。
4. **换模型 / 换 prompt 必须换 `--run-name`**，否则复用磁盘缓存，数字看起来"没变化"。
5. **api_key 不落盘**：一键脚本从 `config.json` 读端点、内存注入；新配置 `config.qwen3-8b.json` 的 `api_key` 是占位 `EMPTY`。
6. **节点描述不进 SFT 输入**：`description_clean` 是客服应答话术，把答案当用户输入是错误监督信号；只留在 metadata 追溯。
7. **`proxy: bypass`**：绕过环境代理，否则 127.0.0.1 / 内网端点可能被 `HTTP_PROXY` 劫持（超时/502 先 `unset *_PROXY`）。
8. **`--source-config` 只取 models**：一键脚本的基础配置固定是 `config.professional.json`（含 intent_routing 任务）；`--source-config` 指向的文件只需含非 mock 的 `models` 数组。
9. **`--resume` 把 error 行当已完成**：补跑必须加 `--retry-failed`。
10. **改了框架源码后**：`python scripts/pack_bundle.py --code-only --list-only` 重生成清单，把 `dist/CODE_MANIFEST.txt` 覆盖到项目根，再 `verify_install.py`。
11. **`--cost-in/--cost-out` 是每 1K token 单价**，示例 0.5/2.0 不是真实报价；不填显示「未配置单价」。
12. **`pack_bundle.py` 的 `INCLUDE_FILES` 白名单已含 `config.professional.json`**（曾漏带导致内网缺文件，已修复）。

## 10. 验收口径（对外结论的硬标准）

- 专业能力：意图准确率相对小模型基线（85.88%）的提升**统计显著** —— McNemar p<0.05 且配对 bootstrap 95% CI 不跨 0。
- 通用能力：退化 ≤ 2 个点且不显著。
- 工程可用性：幻觉意图率、解析失败率、夹带解释率（>2% 先改 prompt 别怪模型）、P99 时延、单样本 token 成本在可接受区间。
- **表述纪律**：测试集只覆盖 53/498 节点（10.64%），对外一律写「在 432 条 / 53 个高频意图上的准确率」，禁止写「全意图树准确率」或「语音导航整体能力」。
